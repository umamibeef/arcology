.. _enhanced-renderer:

=================
The 2.5D renderer
=================

.. container:: eyebrow

   The enhanced world · built · 1 September 2026

.. container:: lede

   What exists of the enhanced world's renderer, and how to run it. The direction and the decisions behind it are on the :doc:`future` page; the original's own drawing, which this is measured against, is on :doc:`rendering-pipeline`. The software rasteriser, ``arcology --soft``, is checked against the original's frame; the GPU path, ``arcology``, is checked against the software rasteriser.

The composition
---------------

.. rubric:: ``arcology --soft --mesh`` · ``--mesh-reverse``

The software rasteriser draws the frame a second way, selected by ``--mesh``: the terrain first, on its own, and everything else afterwards. The terrain pass paints the skirt columns, the ground tile (terrain, zoned-lot ground or a data-view tint) and the elevated anchor's footprint ground, and writes a depth plane holding the painter's index of the tile that owns each pixel. The sprite pass then draws buildings, networks, traffic, the no-power marker and things in the original's anti-diagonal order, tested against that plane and never writing it. Terrain owned by a tile later in the sweep hides a sprite pixel; sprite-on-sprite order stays the sweep's. The underground view keeps the single sweep, because it emits ground and buried pieces together per tile.

This is the composition rule of the 2.5D renderer: the only depth the original ever had is "drawn later in the sweep", and a depth plane that stores exactly that reproduces the painter's algorithm tile for tile. ``--mesh-reverse`` draws the terrain pass back to front, which must change nothing, since the plane and not the loop carries the ordering.

The rejected count is what proves the test: the plane hid over a million sprite pixels behind nearer terrain at 32 px and the frames still match, so the occlusion the sweep used to do by ordering is now done by depth.

``--provenance`` writes a second plane beside the picture, one 16-bit sample per pixel: the id of the sprite that painted it within its art set, with bit 15 set where the shadow pass darkened it afterwards, and 0 for the background. It is what a check of the terrain mesh reads: every pixel a non-terrain sprite painted must survive the mesh unchanged.

The provenance plane
--------------------

.. rubric:: ``arcology --soft --provenance out.png``

A second plane written beside the picture, one 16-bit sample per pixel: the id of the sprite that painted it within its art set, with bit 15 set where the shadow pass darkened it afterwards, and 0 for the background. It is what a check of the terrain mesh reads: every pixel a non-terrain sprite painted must survive the mesh unchanged. Adding it changed no byte of any existing output, checked on eight renders covering the three zooms, the underground view, a data view, a palette phase, a crop and an indexed export.

The shape table
---------------

.. rubric:: ``python3 tools/terrain_shapes.py`` · ``assets/terrain-shapes.json``

Each of the fourteen slope codes built as faces from its corner mask, projected exactly as the rasteriser projects, and compared against its sprite at all three zooms, for both diagonals. The table it prints is the mesh's geometry; what it found about the art is stated with the slopes on the :doc:`mechanics` page: the far edges that slope down from a raised corner are drawn at three pixels per four rows where the projection gives four per five, and code 13 is drawn as a flat tile raised one level. Code 7 reproduces its sprite only when cut from north-east to south-west; every other code is indifferent to the cut.

Running it
----------

All from the repository root, with the game folder as installed:

.. code-block:: console

   cmake --build build

   CITY="$--cities/Manhattan"
   build/arcology --soft assets "$CITY" plain.png --zoom 32
   build/arcology --soft assets "$CITY" mesh.png  --zoom 32 --mesh
   build/arcology --soft assets "$CITY" rev.png   --zoom 32 --mesh-reverse

All three print the same CRC. The two ``--mesh`` runs also print how many sprite pixels the depth plane hid behind nearer terrain. ``--zoom 16`` or ``8``, ``--view``, ``--phase``, ``--crop`` with ``--scale`` and ``--focus`` combine with ``--mesh``; the underground view keeps the single sweep.

.. code-block:: console

   build/arcology --soft assets "$CITY" out.png --zoom 32 --indexed --provenance prov.png
   build/arcology --soft assets "$CITY" out.png --zoom 32 --mesh --depth depth.png
   python3 tools/terrain_shapes.py

``--depth`` writes the depth plane of a ``--mesh`` render as a 16-bit greyscale PNG, full frame, before any crop: the painter's index of the tile owning each pixel, 0 where no terrain was painted. Under a zone building it is 0, because the original paints no ground there; the only terrain that owns pixels in a built-up district is the ground under networks and the open land and water.

The GPU path
------------

.. rubric:: ``arcology`` · ``soft_sweep`` · ``gpu.c`` · ``tools/gen_shaders.py``

The software rasteriser's sweep emits an op list, one entry per blit the original makes, in the original's order, and paints it afterwards; ``soft_sweep`` is that list as a function. The GPU path uploads the same list as instances and draws it through SDL_GPU: the terrain ops first with depth writes, the sprites after them tested against that depth and never writing it, the shadows into a mask, and a resolve onto the window. The depth is the sweep's painter's index, so the composition is the 2.5D one above. The atlases are uploaded as palette indices and resolved through a 256-entry palette texture that the app rewrites when the animated runs turn, so no pixel is resolved on the CPU. Shaders are authored once in GLSL and embedded as SPIR-V and MSL, so a plain build needs no shader tools.

``arcology --check out.png`` draws one 1280 by 800 frame both ways, the GPU frame and the software frame cropped to the same canvas rectangle, and counts the pixels that agree.

Identical means the same CRC over the raw RGB. The pixels that differ are traffic cars, and they are the one place the GPU path approximates. ``$19004`` paints a car only where the destination still holds the road surface, index 0x91, and a fragment shader cannot read its destination, so the shader tests the road sprite's own texel under the pixel instead. The two agree except where the destination was painted by an earlier tile's op: at 16 px a car's art crosses into the next road tile, and the second car is stencilled against the first car's grey. With moving things left out, all three cities are identical at all three zooms. The shadow of a flying thing is applied in the resolve pass by ``$19B76``'s rule on the index the sprite pass left in alpha, which is exact wherever no later sprite painted a dirt-ramp index under the silhouette.

The terrain as geometry
-----------------------

.. rubric:: ``mesh/mesh.c`` · ``arcology --geometry`` · key ``t``

``mesh_build`` follows four rules, listed in the file's header, and nothing else is in it. **One ground field.** Every grid corner has one height, the mean of what the land tiles meeting there say: ``ALTM``'s level plus the slope code's corner lifts, read off the sprites by tools/terrain_shapes.py. Land means land: a tile carrying a structure draws its own pad or plane and does not vote, and a corner among structures only takes their mean, and it is their ground that is meant, not the plane a piece draws on it: a highway ramp's lifted plane had put such a corner a level over the land beside it, a saddle in the field drawn as a pair of twisted brown wedges at the foot of every elevated highway (Oakland, column 104, row 44). A structure does not vote at all: beside a road on a hillside three pads at a level and one land tile a level up put the corner a quarter up, which tilted the land and left a quarter-level tooth of wall along the road at every such corner, the dark notches at the bends of a hill road in Barcelona; now the land keeps its shape and the wall rule closes the whole difference. On 97% of the shipped cities' corners the tiles agree; on the diagonal ramps the mean joins them, and the dark wedge of wall the original's slope sprite shows above a lower neighbour, an artefact of each sprite being drawn alone, is not drawn. Water does not vote: a water tile is flat at its table whatever its low nibble says, so the land around a pond level with its ground stays level with the pond, and a corner no land reaches takes the table there. But a corner that touches water is never below it: the shoreline is at the water. ``ALTM`` keeps one level per tile and the slope code's lifts, and along a shore the land's low corners lie at the bed's level, one below the water they touch, at 725 corners across the 85 shipped cities (73 in Egypt Falls alone, two levels deep at one in St. Christopher). The original never shows them: the water tile's flat diamond at the table, with its sand rim, is painted over them, and the shore reads as level with the water. The mesh, with no diamond to paint over anything, showed a pit at every one, a wedge of earth below the water beside it. Raising those corners to the water they touch is the whole fix; the rest of the tile keeps its heights, so a basin behind the shore stays a basin, as the original shows it. Water is every ``XTER`` from ``0x10`` up: the submerged and shore slopes of a body, and the streams, canals and waterfall from ``0x30`` on, whose table is their level. That is the original's own reading, ``tile_alt`` in the sweep, which places every one of them at the table, flat; the low nibble says where the art puts its rim, not a height. A build that read a stream's nibble as a height, and let it vote, raised Bay View's column 110, row 19, a stream with a slope nibble among flat neighbours, into a bump. **Every tile draws one top face**, at the level the original draws its sprite, and one function, ``tile_top``, says which, for both sides of every edge. Plain land and streams draw the field, cut along the diagonal the sprite is cut along: the one that avoids a single odd corner, which keeps a flat triangle on the other three as the sprite of code 7 shows, and NE-SW for the saddle. Water is flat at its table, a waterfall at its own level, the lower one, so the drop at Bay View's dam is a vertical face of water by the wall rule below; averaged with its neighbours it had been a tilted sheet and a hole. A building or any flat network piece is a flat pad at its level: the tile's ground; one step up for a network piece on a saddle, terrain code 13, as the original draws it (``$17528``: ``cmpi.w #$d``, then -12); the water's table for anything standing on water; and its anchor's level across a building's whole footprint, since ``$1716C`` draws no ground under a building and the art is placed by the anchor, the nearest tile of the same building carrying the rotation's corner bit within a four-by-four window to the north-east. A sloped network piece draws its own plane, and the sloped pieces are a fixed set the shipped cities decided: across every shipped city the power lines ``0x10`` to ``0x13``, roads ``0x1F`` to ``0x22``, rail ``0x2E`` to ``0x31``, highway ``0x3F`` to ``0x42`` and elevated pieces ``0x61`` to ``0x64`` stand on a sloped terrain code every time and every other piece on flat ground, bar a few anomalies such as a road curve on a saddle (Bay View, column 120, row 85). A pad's vertices carry no gradient, so the material shades it as the flat ground it is. **Walls close every difference.** Where two neighbours draw different heights along their common edge, one quad fills the gap between what each draws, done once per edge from the east and south sides: coursed blocks when either tile carries a building, ``XBLD`` from ``0x70``; a face of water where both are water (the waterfall's drop, a dam's spill); earth otherwise, the bank where land stands above the sea, and the step under a network piece, a road curve lifted on its saddle or a slope piece against a corner the field averages, since the original draws the slope under such a sprite as ground and Bay View's hill road at column 26, row 12, had stood on block walls (the ramp of a raised road keeps its own embankment of blocks, below). The quad may twist where the two edges cross and is still two triangles on the same four points, so every edge it makes is shared. **The water is a body with a floor.** Under every water tile lies the seabed, at the bed field: at a corner that touches water, the mean of the water tiles' own beds there (``ALTM``'s level with the shore code's lifts), never above the surface drawn over it -- an earlier build averaged the land's surface into it, which raised a sand spike through the marina at Bay View's column 118, row 16 -- and the ground elsewhere. On every side of a water tile that is not water, the land goes on below the surface down to the seabed. The map's cut edges, the two far ones or all four when the view turns, show the layers of sediment from what the tile draws down to the base, the foundation of a pad or a ramp as blocks above the ground, and through water the glass from the surface to the seabed with the sediment under it; every layer is measured from the bed field, so the layers are continuous across shorelines and under every foundation. Each face carries its tile's painter's index as depth, a wall its tile's index and a half so it stands between its two tiles, so the sprites compose with the mesh exactly as they do with the terrain sprites; the faces are flat-shaded by a sun fitted to the slope sprites, over a material laid out in world coordinates so it does not swim with the camera, described below: of the four plain slopes at 32 px the one facing south is the brightest, mean luminance 135 against 88 east, 84 north and 71 west, so the light stands to the south-east.

**The mesh is watertight, and a test says so**. ``mesh_check`` keys every edge of every triangle on its quantised end points -- heights are means of at most four levels, so forty-eighths are exact -- and counts the triangles on each; an edge with one is free. A vertical edge is a span on its corner's vertical, and the walls meeting at a corner split that vertical differently, so verticals are checked as coverage: every part any edge covers must be covered at least twice. The base of the cut, level zero, is the floor and is closed by definition. ``arcology <assets> <city> --mesh-check`` builds the turned mesh, which cuts all four edges, runs the check, prints the first forty free edges with their tiles and materials and a count by material, and fails on the first; ``ctest`` runs it on Bay View, Cape Wells, Egypt Falls and Felsenschloss, and every one of the 85 shipped cities is closed, 39 to 58 thousand triangles each. One of them, The Bahamas, found a rule short: a marina whose anchor is a land tile one level below the water around it has its pad below the seabed, and the seabed's edge came free; the bed at a corner is now never above the surface drawn over it, the pad included, rather than never above the table. The checker's own test: ``--check-open 1`` checks the plain build instead, whose two uncut edges are open by design, and it reports them. Because both sides of every edge are measured by the same ``tile_top``, the mesh closes by construction, and the earlier per-case rules -- plinths, wedges, banks, filled bridge approaches, a lookup of the neighbour's corners that was wrong for two of the four edges -- are gone with the cracks they caused. ``--no-plinth``, ``--mesh-walls`` and ``--mesh-roads`` went with them; ``--mesh-dump row,col`` remains and prints a tile's kind, corners and bed.

The underground view fills its backdrop white, as the original does (``$15452``), not with the sky. In sprite mode it is the original's: the ground at its own altitude, the seabed under water, the empty tiles' wireframe lattice, the pipes and subways on it, pixel-identical to the software rasteriser. With the mesh on it is the same ground as a mesh, every tile at the ground field and the seabed under water with its slope codes, but only its lattice is drawn: a hairline one device pixel wide at any pixel scale and zoom (the grid's half-width is passed to the shader in canvas pixels, half a device pixel here), every other fragment discarded, so the ground between the lines is the white backdrop and hides nothing. The original's underground ground is a wireframe that hides nothing either: the pipes and subways of the tiles behind show through it, and only a lattice line in front paints over them. A build that drew the ground white with depth had a tile's ground in front covering the subway sprites of the tiles behind, and subways no longer overlapping each other as the painter's order makes them. With the lattice alone drawn, at its own depth, the sprites compose exactly as in sprite mode. The original's lattice shapes are replaced and the pipes, subways and markers drawn over it as before. The lattice is shapes 305 to 318, ``0x131`` plus the terrain code (``$164A2``), emitted by the sweep as plain sprites rather than terrain; the GPU path classified a wrong range, 318 to 331, and only among terrain ops, so the pixel lattice was still drawn over the mesh's hairline. It is classified by shape now, whatever the op's flag, and skipped with the mesh on. ``--underground`` starts there.

A bridge approach, ``XBLD`` ``0x57``, stands on a water tile and is a water tile: its sprite draws the road and its own supports over the water. An earlier build filled the tile to the table because the original's map-edge stack there is a dirt column; that stack is the edge's business, not the tile's. The suspension spans and towers on the water are water tiles the same way. In the colour field a stream reads as a level deep, the sea's blue rather than the shallows' turquoise, since its table is its level and it has no bed of its own; colour only. The plain-sweep switch, a debug mode that draws the sweep's list in painter's order with no depth test, lives in the Renderer window.

**Water is a body.** In mesh mode every water tile's surface is a mesh face, flat at its table and shaded as the sprite decal was, with the same field, noise normals, Fresnel, foam and caustics in world coordinates; the decals are the sprite mode's. The shore is the terrain's own edge, crisp at any zoom, where before it was the decal's magnified pixel outline against the mesh. A marina stands on the water: its pad is the surface itself, calm, no foam and no caustics under the boats. The query tool targets one grid cell: the ground diamond under the pointer at its own drawn altitude, found by iterating on the altitude, so every cell can be reached on its own. The highlight is the whole footprint the cell belongs to, as the original finds it: ``sim_footprint_origin``, the reconstruction's ``$763A``, gives the footprint's edge n and its north-east tile, so it covers rows oy to oy+n-1 and columns ox-n+1 to ox (the marina at Bay View's column 118, row 16 is the 3x3 with its north-east tile at column 118, row 14; the elevated 2x2 pieces pair an even row with an odd column). Its outline is drawn on the surface the mesh draws, each corner from its own corner tile through ``tile_top``, so a building's pad gives a flat diamond of n tiles and a lone cell follows its own plane; in the underground view the corners come from the ground drawn there, the seabed under water. The line is white over dark, so it reads on any ground as the original's inverting outline did, and the query window names the footprint's edge and north-east tile. ``arcology <assets> <city> --scroll x,y --pick wx,wy [--shot out.png]`` prints the pick, the footprint and the outline's window points, and with ``--shot`` writes the frame with the query window and the outline on it, for checking without a pointer.

**One ground field**. The field is the first rule above, and every pad, plane and wall stands on it without changing it. The layers of every cut are measured from the bed field, so they are continuous across shorelines and under every foundation; the glass carries the bed per vertex, so the cut is continuous across tiles where the bed steps; a water tile on a cut edge draws its surface as a mesh face shaded exactly as the decal shades it, so the water meets the cut in a straight line at any zoom instead of the decal's stair-stepped diamond edge against the straight face.

**Roads, rails and power lines as geometry**. The reference for this work is the road system specification, reproduced whole as :doc:`appendix-road-spec`, its part 5 on railways included; its feasibility against the save format is tabled on:doc:`future`, and what follows is what is built. With the 3D world on -- the T key, the View menu's Geometry or ``--geometry``, which is one switch for the ground, the water and the roads -- geometry replaces the sprites of the three network families that share one fifteen-piece layout, power lines at ``XBLD`` ``0x0E``, roads at ``0x1D`` and rails at ``0x2C``, and of the six crossings ``0x43`` to ``0x48`` that carry two families on one tile, with geometry on the surface (``K_ROAD_ART``, classified by shape id; the tunnels ``0x3B`` to ``0x42``, the highways from ``0x49`` and the bridges keep their sprites). The crossings were read off every shipped city's neighbours rather than a table: ``0x43`` is a road east-west under a power line and ``0x44`` a road north-south under one, ``0x45`` a road east-west over a rail and ``0x46`` one north-south, ``0x47`` a rail east-west under a power line and ``0x48`` one north-south. An earlier table had ``0x44`` to ``0x46`` turned and lacked ``0x43`` and ``0x48``, so a power line stopped at every road it crossed and the crossing stayed a sprite among the geometry. With the road mesh on the traffic sprites and the train sprites stay off, since a pixel car on a modelled road is the wrong kind of thing (``K_CAR``, the stencilled sprites of ``$19004``; ``K_TRAIN``, shapes 374 to 378), and both are drawn as geometry instead. A train is one thing record per car, types 10 and 11, found through ``XTXT`` as the original finds them, each a turned box on the track for its direction, right-hand running as the specification's signalling assumes, along the axis of the rail piece under it and facing by the record's heading; the engine is type 10 and darker. The road cars move. The mesh keeps the road network it lofted, every segment's stations with the band's height and direction, its class and its two nodes, and the traffic lives on it: each segment is seeded with as many cars as the original's rule would give sprites, a tile past traffic 0x55 one and past 0xAA two, capped at a car and a half per tile of length and 2,500 in all; each car runs along its segment at a tile or so a second, in the right-hand lane of its direction at the lane centre its class draws, an avenue's outer lane and for a third of them the inner, holds behind the car ahead in its lane, holds at the stop line while the signal on its arm is not green, the same phase and cycle the lamps draw, crosses the junction box to a random onward arm, and turns back at a dead end, a map edge or a carrier. The cars are rebuilt into a buffer of their own every frame and drawn after the mesh. A car is a body and a low cabin, 0.15 of a tile long and 0.065 wide, less than a pixel tall at the base zoom, painted by the car; a train car is a rigid box 0.42 of a tile long and 0.10 wide, on the chord between its two bogies 0.14 each side of its centre along the path. The trains move too: the mesh keeps the rail network as it keeps the road's, a run of consecutive records on adjacent tiles in the save is one train with the type-10 engine at its head, and the engine runs along its segment on the track to the right of its direction while every car trails it by arc length on a ring of the engine's own path, coupled 0.48 of a tile apart, at 2.4 to 3 tiles a second, so a train follows a curve car by car and a reversal at a dead end makes the tail the head. Across a junction box a vehicle that turns, a train onto a T's branch or a car onto a side road, follows a curve tangent to both arms through the corner where the arms' lines meet, the junction's own curve, rather than the chord across the box; straight through it crosses on the chord. At a turnout the engine takes the straightest arm. The crossings' gates and flashers belong to the same per-frame buffer: an arm lowers over two seconds while any car of any train stands within eight tiles of the crossing along the line, three seconds of warning at the trains' speed and the second-train rule of 3.15, and rises over three when the line is clear, its flashers alternating whenever it is off its rest; the arm is a bar 0.02 of a tile wide in red and white stripes, clipped to the tiles it reaches across (it had been a hair of 0.006 with its stripe code in the channel the lamp material does not read, a white thread no zoom could show). While the flashers are on, every road car on the segment through the crossing stops with its front at the stop line, 4.5 m before the nearest rail, and the cars behind queue on it; the crossing's place on the road network, its segment and the distance along it, is found once from the nearest station to its tile's centre. Every vehicle pitches with the grade, its ground read a half length ahead and behind; vehicles are objects, not the surface, and the checks leave them out. Every face of a vehicle is clipped to the tile grid as the road's are, each piece in the depth slot of the tile under it: a car had carried the slot of the tile under its centre, and the part of it over the next tile toward the viewer lay under that tile's ground until the centre crossed, when the whole car stood up at once. Within its tile's slot a vehicle's depth follows its place along the tile's diagonal toward the viewer, a tenth of a slot across the tile: the depth is the painter's index, not distance, so two cars overlapping in one tile, on the inside of a tight bend, had been resolved by draw order and fought. Which edges a piece joins is read once from the road art, the asphalt or a dash in the three-by-three around each edge's midpoint a tenth of the way in, and the other two families take the road piece at the same offset; a slope piece is straight along its slope, which the terrain code says. A road or rail is not drawn tile by tile but as segments, the specification's part 3.10. The network's nodes are its junction tiles, a piece of three or four links whatever its neighbours return, and its end tiles, whose piece has one link a neighbour returns; every other tile lies on one segment, and each segment is walked once from a node to the next node, through loops without a node too. A link counts only when the neighbour's piece links back, or when it leaves the map, where the road runs to the tile's edge: a piece whose art points at grass, a stub against the flat side of a T, a road bulldozed short, all end there at a butt end, as the original draws every such sprite as it is. A piece no neighbour joins is drawn on its own, a band across its tile. Before that rule a chain with no node at either end, a road from map edge to map edge or a stub cut short at both ends, was never walked and its tiles went undrawn, their sprites skipped and nothing in their place; a scan in the check below counts them, and across the 99 shipped cities and scenarios the count is nought. Its centreline is the polyline through its tiles' centres, from the side of the junction box it leaves to the side it reaches. That polyline is not straightened by rule any more. The path is fitted in stages, and the stages are the design: the tiles a highway, road or rail segment stands on become the HALLWAY it may pass through; a segment is swept through its hallway as a curve, which the small width these networks are given is what affords; crossings, on-ramps and interchanges are taken into account where the networks interact; and the pieces are rendered accordingly. Because a segment is the unit, breaking a tile recalculates only what is in that segment's adjacency graph. The first two stages are ``mesh_path.c``. A segment's tiles are its corridor, the room it may use, and between each pair of them lies a gate: their shared edge shrunk by the band's half-width, so a band through the gate passes through whole. The line then starts at the gates' midpoints and is relaxed -- each point moves toward the mean of its neighbours, then back onto its own gate, forty-eight times over -- which converges on a line straight where the corridor is straight and cutting a staircase into one diagonal because the gates allow it. Coverage holds by construction: both ends of every run lie on one tile's edges and a tile is convex, so the line can neither leave the corridor nor skip a tile, and no piece of road is left with nothing drawn over it. Each joint is then swept on the largest radius whose arc still stays in the corridor, which is what a band narrower than its tile buys. The taut string through the gates, the shortest path, was written first and thrown away: it hugs the inside of every bend, so the band runs along one wall of its corridor and 453 tiles of Bay View's roads had no geometry over them. What this replaced was a straightener that tried to recognise a staircase, a jog and a zig-zag from their leg lengths and their regularity, refused joins that landed too far away, and cut a rail's corners in a pass of its own; every city turned up a case its rules read differently from the eye, and it is gone from the road and rail path. The stages are worked on from above, with ``--path-dump 1`` and ``tools/plan.py``, which draws the corridor, its gates, the fitted line and the band. Every face of the strip is clipped to the tile grid and each piece carries the painter's order of the tile under its own centroid: a quad that straddles two tiles had carried the order of the tile under its midpoint, and the later tile's ground was drawn over the part of the quad inside it, a wedge of grass cut into every arc and every diagonal at each tile boundary, the notches at the bends of Barcelona's hill road that the field's teeth had not accounted for (Barcelona's rail at column 106, row 10; Oakland's bends); a face lying wholly in one tile takes that tile's order too, not its caller's. There is no join inside a segment, and a segment meets its junction box square on at the box's own width. The road's profile is, at each station, the highest ground the cross-section spans, centre and both edges, and a hair above it, with a station every eighth of a tile and one wherever the centreline or either edge of the band crosses a tile edge, found by bisection and read on both sides of the edge, so a crest at the edge between a rising and a falling tile, or a small wall the band crosses obliquely, is met at a station and never the underside of a chord; then the grade is capped at one level per tile of road, the original's slope pieces' own pitch, by raising stations and never lowering them, with the two ends pinned to their nodes. So the terrain never cuts through the road: a road along a slope lies on it, a road across one rides on its uphill edge, and a straightened diagonal crossing the unlevelled corner tiles beside its road tiles rides over their ground; wherever that lifts the road above the ground at an edge, a wall of coursed blocks runs from the road's edge down to the ground, the embankment the pads have. A running maximum over half a tile was tried first and rejected: on a uniform slope it lifted the road above its own ramp and grew a wall down every hill. The profile is then filleted as the plan is: it is averaged over half a tile each side, which rounds every grade break into a curve a tile long, about a metre off the break for the art's one-level-per-tile grade; at a sag the road rises off the ground onto its embankment of blocks, at a crest it sinks into the ground behind a retaining wall of blocks from the ground down to its edge, facing in, in the embankment's own material so the watertight check leaves it out with the strip, and the ground inside the band is painted over by the road, which in the sweep's depth stands in front of its own tile's ground whatever its height. The ends keep their height, a junction box, a carrier or a cap on the ground, the rounding fading in over the half tile from each. A quad in a cut is flagged in its class, four and up, so the clipping check, which otherwise forbids ground over a road, passes it. The ground in a cut follows the road rather than being carved for it: where a vertical curve sinks a road below the ground, the corners of the tiles it passes through, those the band reaches, are capped to a hair under the road, and the mesh is built a second time on that field, so the terrain bends into the cut and the walls close what is left. The height is one per grid corner, shared by the four tiles around it, so the bend is continuous and no face has to be split; a corner is only ever lowered, and never by more than a level, which no vertical curve asks for. A carving pass was built first and withdrawn: clipping every surface face against the cuts' outlines split faces whose neighbours across a tile edge stayed whole, and the T-junctions that left had to be welded away and the watertight check taught to forgive what remained. The grade cap came from Bay View's hills: where a fillet climbed across a slope piece, the profile rose a level in under half a tile, and that near-vertical face, shaded by its own tilt, drew as a black patch the road seemed to vanish under. It was not the terrain: ``mesh_check_roads``, run by ``--mesh-check`` whenever ``--roads3d`` is on, samples every road face on a barycentric grid, strictly inside the face since a sample on an edge reads the tile across it, and counts the samples a terrain top face stands more than two hundredths of a level above, a fifth of a pixel at the base zoom; Bay View had sixteen tiles under a level and now has none; over the 99 shipped cities and scenarios, none has any. The same run counts every road, rail or power tile that no network face touches, so a piece the walk could not draw is a failure rather than a gap; the four ``mesh_watertight`` tests run with ``--roads3d`` and fail on the first of either. ``--clip-dump 1`` prints each penetrating sample with the faces over it and ``--tile-dump col,row`` every face on one tile. Asphalt and paving keep their colour on a slope, as the sprites' slope pieces do: a third of the shading follows the tilt. The embankment carries its own material, so the watertight check, which counts every wall of the surface, leaves it out with the strip. An end against open land ends at the tile's centre with a round cap of the band's width, whatever the road's class and whatever stands beside it; an end against anything from ``XBLD`` ``0x3B`` up, a tunnel end, a highway, a bridge or a building, runs square to the tile's edge, as the original draws the straight piece whole and the carrier's sprite goes on from there (a build that capped every end put a turning head at the foot of every bridge). A rail always ends square. The underground view builds no road geometry. ``--road-dump 1`` prints every segment's polyline after straightening. The road strip is 0.71 of a tile wide, one width in the world in every direction, the width the road tiles of a 1:1 staircase inscribe, tile over root two, and across it, from the crown out: the asphalt of the sprites' palette to 0.8, a curb, and the sidewalk, concrete slabs scored every half tile, as the band's outer fifth each side. Beyond the band the tile's own ground shows, the grass margins the sprites have; a build that paved every road tile to its edges under the band, one face per tile, made a sawtooth of slabs along every diagonal and, on a hillside, terraces of concrete stepping down the slope, and is gone. A junction is a box of the band's width with the sidewalk and curb along its free sides, and where two arms meet, a curb return, the sidewalk's corner rounded on a fillet of its own width; the box, its sidewalks, its returns and every end cap stand the hair above the ground the strips do, 0.03 of a level, since on the ground itself under arms a hair higher the oblique view had shown a line of grass along every side of a rail box. Its class follows the traffic, one class for the whole segment, the median of its tiles', so a centre line does not start and stop mid-block with each tile's count: a two-lane road with the sprites' light dashes, nine to the tile; an avenue, traffic 64 and over, with a double yellow centre line and a dashed lane line each side; a boulevard, 160 and over, with a planted median between curbs, which ends at the junction box, plain asphalt. Every line is the art's width, one pixel at the base zoom, never thinner than a device pixel and never wider than a fixed fraction of the strip, since the screen derivative the width is taken from swells in the sliver triangles at an arc's ends. The oblique camera draws a road running toward it wider on screen than one running across it, as it draws everything else; a build that scaled the world width by direction to equalise the screen width was rejected as inconsistent and is gone. The crosswalks lie on the approach tiles, which have the room the junction tile lacks: a straight road leading into a junction gives its last fifth to a band of white bars across the asphalt, six to the width, with the solid stop line at the band's outer end. A junction's arms are controlled as the specification's 3.4 tables it, from the classes of the roads meeting there: four local legs get a two-way stop on the quieter axis, a T with a local stem a stop on the stem, a local against an avenue stops on the local legs, avenue against avenue is an all-way stop or a signal where the junction is busy, and anything against a boulevard is signalled; a stop-controlled arm gets a STOP sign at the driver's right behind the crosswalk, an uncontrolled leg no crosswalk and no stop bar, and the cars stand a second at a stop sign and go. Where an arm is signalled it gets a signal, as the sprites carry a light at every T and crossing, sized by the specification's part 6 at the road's scale of fifteen metres to the tile and eight to the level, as are the street lights (1.6, 6.4: on an avenue or boulevard a cobra-head luminaire every two tiles, staggered side to side, a pole on the sidewalk ten metres tall with a three-metre arm out over the road; a local road goes unlit, its post-tops a downtown's), the crossing masts, plaques, flasher bars, gate mechanisms and arms, whistle posts, second-train signs and block signals: a pole at the driver's right-hand corner of the box, a mast arm from its top out over the road to the centre line, and a three-lamp head hanging from the arm's end with its lamps facing the approaching traffic; the lamps run a twenty-second cycle on the junction's own phase (the specification's 3.4 timing, scaled to the sim): north-south arms green six seconds, amber two, then an all-red clearance of two before the east-west arms' green, then the swap. A railway is a double track, one track for each direction, since the original runs its trains on a single track in both directions and lets them pass through one another. It is sized against the road as the road is sized to the tile rather than to the sprite or to metres: one ballast strip 0.62 of a tile, about a road's width, the two tracks 0.27 of a tile apart, the specification's 4.0 m at fifteen metres to the tile, and on each track timber ties 2.6 m long at 600 mm, twenty-five to the tile, fading to their mean where they pass a pixel's period, and two rails at the 1435 mm gauge, a tenth of a tile, each a device pixel at least and drawn light, their polished heads seen from above, since dark rails on dark ties had merged into one line at the base zoom. It is bent and joined by the same rules; where it crosses a road, the crossing tiles ``0x45`` and ``0x46``, the crossing surface is the road's and only the four rails show through it, flush, drawn a hair above the asphalt, and the crossing is built as the specification's 3.15 draws it for a double-track mainline: one surface of dark rubber panels across both tracks, the road's width and its sidewalks, with the rails alone showing through it; on each approach, at the driver's right, a mast with the crossbuck, a two-track plaque and a pair of red flashers, a counterweighted gate post beside it with a red-and-white striped arm, a stop line across the approach lane 4.5 m before the nearest rail, two fifths of a tile, and a second-train sign facing the end of each sidewalk; from a tile and a half out the approach's centre and lane lines are solid and a large X is stencilled in each lane a tile out. The gates are down and the flashers alternate while a train stands within three tiles along the line, and are raised and dark otherwise, since the save says where every train is. Median flashers wait on a boulevard with a raised median; a rail junction is a wye of tracks routed between its arms' ports and lofted within its reach (the turnouts, below). The line is signalled as 5.6 has it, right-hand running: a colour-light block signal every ten tiles, an absolute signal a tile before each junction, a whistle post two tiles before each level crossing, each signal's aspect the traffic's, red while any car of a train stands in the ten tiles ahead of it and green otherwise. The signals are scenery: a train does not stop at a red one. A power line is a pole at the tile's centre with a crossbar and a wire, sagging a little, to each joined edge's midpoint, where the neighbour's wire meets it; over a road or rail crossing there is no pole and the wire spans from edge to edge. Every strip and prop samples its heights from the drawn surface at each vertex's world position, whichever tile holds it, and the vertex shader lifts them a fifth of a depth slot over the ground so they win over the ground and stay under the tile's sprites. They are decals and props on the surface, not the surface, and the watertight check leaves them out. A deck is a structure, not a carpet: its support line may rise or fall no faster than a sixth of a level a tile, so it runs straight over what the ground does under it and the columns take up the difference, and its proportions are measured off the original's own rendering rather than the specification's concrete sections, which built a viaduct of walls. It carries freeway markings of its own, a median barrier with three lanes each side and no yellow line, where it had worn a surface road's class. A viaduct is a closed structure: the carriageway on top, a concrete soffit under it, the girder's fascia and the parapet along each edge, and a wall across each end where the deck begins in the air; every face of it is clipped to the tile grid like the road's, since a soffit triangle straddling two tiles with one painter's order was drawn over the next tile's carriageway. It stands on round columns, twelve-sided prisms footed a third of a level into the ground, under a cap measured against its own ground so it does not step on a slope. The concrete carries its own material, with a depth bias that keeps the structure behind the deck it holds up, and what a viaduct flies over is drawn under it, the road or the line the crossing pieces ``0x4B`` to ``0x4E`` stand for, which had left nothing at all on those tiles. A highway's band is walked as a road's polyline is, and wherever it goes: straight on while it can, through a curve block, ``XBLD`` ``0x65`` to ``0x68``, whose four tiles carry the highway through a right angle and whose centre lies on both seams, or a step sideways. The art draws a diagonal highway as a chain of those blocks touching at their corners, so the walk follows the chain block by block, taking the step across before the step diagonally, and the centres come out as a staircase of two-tile steps. That staircase is straightened into one line, as a road's is, a highway's band being wide enough that the midline of such a step stays inside it where a road's would not, and every bend is then filleted on a radius of two and a half tiles, so the curve begins well before the corner and ends well after it. The sprites of everything the band lofts, the decks, the ramps and the curve blocks, are dropped with the road's; the long inclines, the bridges and the corner fills beside a curve keep theirs, since nothing meshes them yet. An elevated highway's band takes in its ramps, ``XBLD`` ``0x61`` to ``0x64``, whose axis is the deck's they carry, read off the shipped cities: the deck's lift tapers over them, from its height where the elevated tiles begin down to the ground at the band's outer end, so a ramp is a ramp and not a carriageway ending in mid-air over the field; a ramp tile draws no plane of its own under it, since its deck is drawn above it. The corridor is a room in the vertical too, and that is being built: ``--notch 1`` grades a smooth surface along each corridor, notches the corridor's tiles out of the terrain to sit on it, and walls their sides with coursed blocks, so a road on a hillside is a shelf cut into it rather than a ribbon draped over it. It is not the default yet: the mesh stays watertight with it on, but where several segments meet at a junction their graded corners disagree, the tile's surface then rises through the band, and the clipping check counts it. Until the surface is one fit per tile rather than four corners fitted apart, the default keeps the older behaviour, in which the band is drawn a hair over the ground and the ground is capped under it. The renderer has a map view, the camera straight down as the original's map is: the ``N`` key, or ``--plan``. Looking down, the depth is the height rather than the sweep's painter's slot, which is the one view where the slot cannot help and does not have to, and the sprites are dropped, since isometric art cannot be looked at from above. The zones are painted over it as translucent tints, residential green, commercial blue, industrial yellow, the darker shade for the dense zone; they are geometry like everything else, thrown outside the frustum by the vertex shader unless the camera is looking down, so they cost the oblique view nothing. Not yet built from the specification: control by class, lane assembly, the ENCROACH and THICK policies, furniture beyond the signals and poles, and moving cars. Sheet: ``out/closeups-roads.png``.

**A shared leg is split by demand**. The corridor was never the limit there -- 89,77 is trees, and trees are free air under a deck -- the fit's tangent budget was: an edge between two corners was split half and half, so the right angle at 91,79 got 1.25 of a 2.5-tile leg and a radius of 1.25 while the 26-degree bend beside it wasted its half. A fillet of radius r needs r tan(turn/2) of tangent, so the edge is now split in that proportion (``tf_demand``) and both corners come out with the same radius: 2.02 there, the bend 2.02 instead of 2.37. Road clip over the shipped cities is unchanged.

**Lanes as primitives** (:ref:`the plan <future>`; ``src/render/net/lane.c``). Every road segment derives its two lanes from the same fitted, trimmed pieces its strip is lofted from: the with-path lane offset to the viewer's right, the against lane to the other side and reversed, so each runs the way its traffic does; an arc offsets to a concentric arc, a run to a parallel run. A lane's end names a junction *port*, the arm's mouth on the viewer's right of the heading. The router, ``lane_route``, fits the lane between two poses: a straight when the goal lies dead ahead, else the equal-tangent biarc built by the same piece builder the road fit uses, and reports the tightest arc. At every road junction a connector is routed from each inbound lane to each outbound lane of the other arms; a two-lane four-way has twelve. The junction shapes itself from them: at a right angle the corner where two arms' edges meet is the mouth line, so a lane turning there pivoted on a point (a centre radius of 0.125); the mouths now move out by the curb return's tangent length (``JUNC_CURB`` 0.20 at the default width, under the trim cap), the outline carries the concave arc between the tangent points, the footway follows it round, and the right turn sweeps 0.325, six metres at the tile's scale. The port takes the trim the segment will actually be cut at, including the scaling a short segment between two junctions gets, so every lane end meets its port (the check counts the misses). Under show curves the lanes draw as red lines and the connectors as blue, over the asphalt; the corridor and free-air markers are flat blended tints on the tile's own top, tan and blue, under the roads. ``--lane-dump C,R`` prints a junction's ports, connectors and the lanes reaching it; a bare ``--lane-dump`` prints the tight turns and the misses city-wide; the mesh check's ``lanes`` line gives the totals. The standing rule for what comes next: a lane's asphalt is lofted by ``loft`` with the lane's own width, never by a second emitter. **The ramps are the first to follow it** (stage 2): a ramp is one routed lane in two legs, both the router's biarc between two poses. The descent runs from the deck's outer lane at the gore's near end, heading along the deck, to the foot, the middle of the ramp tile's road-side edge heading at the road; the join runs from the foot into the road, onto a stub's lane on the ramp's side a quarter of the road's width off its centreline and out to the road tile's far edge, so the road's lanes are the ramps', or onto a through road's side thirty degrees off its line. Both legs are built deck-to-road, the deck end heading away from the gore, and an ON ramp is reversed; the height eases from the deck to the road as before, and the same ``loft`` lofts it with the lane's flags. Atlanta 87,80, 72,88 and 70,88 route with radii from 1.3 to 4.7 tiles on the descent and the stub's fillet at 0.33 and 0.66; ``--lane-dump`` prints every ramp's poses and pieces.

**Every lane end is a lane end**. The deck's six lanes are in the table, three each way at the centres the material marks (0.255, 0.55 and 0.82 of the half width), recorded under the band the loft records its stations under; a rail line's two tracks are lanes at 0.133 from its centreline; an avenue and a boulevard carry two lanes each way at the offsets the traffic code places its cars (0.115 and 0.306, 0.162 and 0.317 of the road's width), a road one at 0.200, with a port and a connector per lane at the junctions, inner to inner and outer to outer. A ramp snaps both ends onto recorded lanes through ``lane_nearest``: the deck's outer lane of its band at the gore, and the road's lane at the join, the near lane running the ramp's way for a through road, including a road on the far side of the ramp tile; a ramp is then a lane of its own whose ends name them, and the check counts any end that found none (Atlanta: 54 ramps, none). Show curves hides every network material through one rule, ``curves_hidden``, so the overlay stands on bare ground: lanes red, tracks brown, deck lanes light grey, connectors blue, ramps red.

**Every open lane end is looked at**. After the ramps, ``lane_transitions`` visits every deck lane's open end. Where a road's lane end faces it, the inner deck lane routes into the road's lane and the middle and outer lanes taper into the inner one a tile and a half and three tiles up the band. Where the walk cut the deck into bands, at an interchange or a corner, each lane goes on into the next band's lane of the same offset magnitude, running on or turning up to a right angle, within six tiles: a lane is the right-hand lane of its own travel whichever way the walk ran its band, so the offset's sign is not a side. A band too short to taper is a connector piece and links lane for lane. An end that meets nothing is counted; in Atlanta the eight such ends are the four bands leaving the map. A dead-end road's lanes connect round its cap, lane for lane, by the biarc between two facing poses a lane's offset apart, a semicircle inside the round cap the loft draws there. Under show curves a ramp's wire eases from the deck's height at the gore to the ground at the road, as the lofted lane does, so the overlay shows it meeting the deck's lane where it does. The check line: ``24 band ends (8 meeting no road, 48 on to another band), 64 links (0 failed); 20 dead-end caps (0 failed)``.

**The build walks the map once**. The measuring walk keeps every segment it fits in a table, ``s_segs``, with its pieces, the fit's nodes, its corridor tiles, the tiles it marked visited, its nodes and its class; the drawing walk reads the segment back instead of walking and fitting it again, and the building pass replays the arms and crossings from the table rather than walking at all. One fit per build, where there were four. The two passes are an explicit driver, ``mesh_build``, over one body: the grading pass draws nothing, skips the junction boxes and the lanes, but still lofts the ramps, because a ramp's loft caps the terrain field and the field is smoothed as a whole (skipping them moved a road's station ninety tiles away by a hundredth). ``--no-replay``, ``--grade-all``, ``--grade-junc`` and ``--grade-lanes`` turn each of these off for a comparison; ``--tile-dump all`` prints every triangle's material and tile for a whole-mesh diff. Atlanta builds in about 75 ms, the second pass's measure in 0.4.

**Every lane end goes somewhere**. A ramp beside a junction is an arm of it with one port, outbound for an ON ramp and inbound for an OFF ramp, at the tile edge's middle where the ramp's own lane ends; the junction's connectors feed or drain it, and the ramp has no join of its own into the box. That holds where the box is a junction of roads -- three or more arms that lead to road tiles, the crossing with lights -- or a stub, the road ending in its ramps, and also at a bend whose through movement is the ramp: two road arms with the ramp straight ahead of one of them, where that arm's lane alone reaches the ramp's port and the box offers it straight-on or the turn. The data puts a crossing piece beside every ramp, and where two road arms pass the ramp at its side the box is a road for the lanes' purposes (``lane_ramp_arm``). The ramp table is made before the junctions so a junction can see the ramp beside it, whether or not the data counts the ramp tile as a road link. Rail junctions get their tracks' connectors too, a line is joined straight through a crossing tile, a line the walk broke at a tile's centre is one lane again, a rail terminus reverses, and an arm off the map's edge has no ports. ``lane_check_ends`` then counts every lane end at a port no connector leaves, every start at a port no connector reaches, every open end no link or cap covers, and every connector whose port has no lane: the ``lanes`` line ends ``N ends with nowhere to go, M starts with nothing arriving``, zero in Atlanta and Toronto. A ramp joining a road away from a junction narrows over its join from the deck lane's width to the road lane's (``RLoft.taper``), so it arrives as a lane of that road and not a strip across it.

**A ramp takes one lane**. Where a road passes a ramp, the ramp's lane peels off or merges into the near lane alone -- the kerb-side lane of a four-lane road (``lane_nearest_outer``), or, inside the crossing piece's box, the nearest of the box's straight connectors. Where the box is a real junction, each arm gives the ramp its outermost lane and no other. Every ramp tile is marked orange on the ground through the highlight pipeline, shown only with the grid outline. Atlanta: 54 ramps, every one on a lane, zero lane ends with nowhere to go; the same over the shipped cities.

**What the close-ups taught**. A ramp arm returns no road link, so the box hull had ignored it and stopped half a road-width short, with grass between box and ramp: the hull now takes a ramp arm to the tile edge whether or not it is linked (``jp_arms``). The box's footway band is the junction's sidewalk: mitred at the outline's vertices, drawn as concrete in the sidewalk material plus a curb in the road material's curb zone over the box, on every edge that is not an arm's mouth -- a mouth being an edge whose two ends carry the same arm, whatever its width (an avenue's mouth had been banded: "you have a sidewalk in the middle of the road"). The square box's own side and corner pavement is gone; it lay on the band and fought it. A one-tile jog between parallel lines is a 45-degree diagonal with a 45-degree corner at each end, crossing the two tile edges at their middles, with half a tile of straight kept before and after it (the fit's walked fallback; 66,113 and 65,113: "should have been a diagonal"). A road ending against a building gets its turning head INSIDE its own tile, the strip stopping a cap's radius short of the edge (``end_point``; 91,53: "why is the cap not generated within the cell? you're creating a cul-de-sac basically") -- on a flat tile; on a slope the flat cap cut under the ground (Bayview 116,13), so a sloped end stays square, as do ends against a bridge, tunnel, crossing or highway, where the road runs on. The ramp's jaggies at 87,80 were stale width factors: the loft's station buffer is static and only a deck's lane drop had set ``wl``/``wr``, so a ramp lofted after a deck kept the deck's gore taper at whatever stations shared an index; every loft resets them after sampling. Painted markings sit 0.004 of a slot nearer than their surface. In the map view every network tile is tinted -- roads grey, rails yellow, highways purple, ramps orange -- as a translucent lid at the top of the tile's slot (paint 8 to 11, shown only with the grid), and every cell may carry its own col,row at its bottom-right corner (View > Cell coordinates, ``--cells``, remembered in the preferences with the grid and Show Curves). ``--plan --centre`` now lands the tile: the headless hold pivots on the anchor as the app does.

**Sidewalks as a primitive**. A sidewalk is a path with two ends and every end meets another's: a road strip's two sidewalks, the outer fifth each side, registered by the loft from its first station to its last; a junction's, registered by the box as the run of its outline from the end of one mouth to the start of the next, curb returns and free sides alike, so a mouth cannot be banded by construction; a dead end's, round its turning head. Each end knows its way out, so an end that stops at a carrier -- a bridge, tunnel, crossing or highway the road runs on into -- or at a ramp's mouth is not a miss. The drawing is unchanged and goes through the same lists; the mesh check's ``sidewalks`` line counts the ends that meet nothing, ``--walk-dump`` names them with the nearest other end. Atlanta: 2614 strips, 2515 junction links, 14 caps; 220 open ends, in two classes the primitive found -- bends the walk broke into two strips at a tile's centre with no corner piece between their sidewalks, and strips cut 0.12 short of a junction's mouth -- both the next round's work.

**Three passes of their own: markings, sidewalks, furniture**. A pass is a DRAW, not geometry. The loft emits one quad per station pair, the whole band, into the opaque list after the terrain; the frame draws that network range once as the base and again once per pass that is on, with the pass number in the frame uniform (``gpu_frame.c``): pass 1 is the sidewalk pass's, where the road material paints a strip's outer fifth, curb and concrete, and nothing else; pass 2 the marking pass's, where it paints the lines alone at equal depth, on roads, crosswalk bands, crossing approaches and decks; the base draw paints asphalt and discards both. The same vertices every time, so Atlanta stays at 576k triangles with every pass on, and switching a pass is a draw skipped, no rebuild. What each module owns: ``marking.c`` the marking decisions the loft asks for at build time and the pass's draw; ``walk.c`` the sidewalk primitive, the junction's band and the cap's rim as geometry, and its draw; ``furniture.c`` everything that stands on a road or a railway, built in, including the gate arms and rail-signal aspects the traffic decides per frame and hands to it. Switches: View (Road markings, Sidewalks, Street furniture), ``--no-markings`` / ``--no-sidewalks`` / ``--no-furniture``, remembered in the preferences; only furniture rebuilds. An intermediate version emitted separate quads per pass and cost 1.25M triangles: the wrong direction for a larger world, and replaced the same day.

**Chunks**. After the build the opaque list is bucketed by chunk, 32 by 32 tiles, 16 on a map, and within a chunk terrain first and networks after: a stable counting sort of the triangles by the tile their first vertex lies on (``mesh_bucket``), so the triangle set is untouched and the sorted tile dump hashes the same. The mesh carries 32 ranges; the frame draws each chunk in view as its terrain range then its network range, and the passes draw the network ranges of those chunks alone. In view is decided by the chunk's eight corners, its four tiles at the ground's floor and its highest level, put through the very projection the vertex shader applies, turn, pitch and lift, with a twentieth of margin: Atlanta at a close zoom draws 4 chunks of 16, the whole city 13, the map view close in 2. This is the substrate for the rest of the programme: per-chunk rebuilds on an edit, per-chunk pools, and a description cache keyed per chunk.

**Rebuilding after an edit** (the next brick of the same programme). The mesh keeps a snapshot of the city it was last built from and the key it was built under (the view, the knobs, the furniture switch); the next build diffs the tiles against it, and a small change under the same key (fewer than an eighth of the tiles) is built as an edit (``mesh/incr.c``). Which chunks an edit reaches is a closure over the tables the grading pass leaves behind: a segment whose tiles touch the dirty tiles' neighbourhood has a new fit, so the junctions at its ends have new boxes, so every segment ending there has new trims; a highway band within two tiles has a new fit, and so has every ramp on it and the road at each ramp's foot; a ramp beside a changed junction has a new join, and its band carries the lane drop. Their tiles, dilated by a tile or two, name the chunks. The building pass then runs whole, so every table the traffic and the lane checks read is complete, but the terrain loop skips the tiles of the other chunks (a tile builds when its own chunk or a neighbour's does: its faces reach a quarter step past its edges and its walls stand on the far edge) and the one triangle emitter drops what falls outside them, keyed exactly as the partition keys. The partial list is sorted by chunk and spliced into the previous mesh range by range, the water list the same, and a check that every range holds only its chunk's triangles is part of ``--mesh-check``. The proof is ``--edit C,R[;C,R...]``: build, demolish those tiles, build again, and the sorted tile dump of that build must hash the same as ``--no-incr``'s full build of the same city; eighteen edits on Atlanta (mid-segment, junction, ramp foot, deck over a road, a building, the map's corners, the coast) do. What it saves at this size is modest, a full build's 86 ms becoming 68 to 74, because a build's cost is in walking and sampling every segment for its lanes, sidewalks and graph, and that still happens; the edit's build only spares the emission and the untouched chunks' terrain. The next brick keeps a segment's products across builds, so an untouched segment costs nothing.

**A segment's stations kept across passes and builds**. A stage-by-stage profile of the build (``--times`` now prints one line per pass: walk and fit, trims, lanes, overlay, caps, and the loft's sample, ground, profile, record and slab) put the cost where it was not expected: the lane model is nearly free, and a third of a build was the loft sampling every segment's stations, once in each pass, with the grading pass then running the slab's arithmetic for triangles it throws away. **Why a corner is as tight as it is, and the knobs**. One more thing came out of the day: the two new knobs made the mesh's build key longer than the incremental rebuild's snapshot buffer, so every city's snapshot was silently refused and every build ran whole, which the corpus sweep never saw because the failure was not a check line. The buffer is larger, and the sweep compares that line too.

**One depth, the camera's**. At the game's own view the depth buffer had held the sweep's painter's slot per tile, the mesh in the middle of its tile's slot and the art at the top, the art testing depth and never writing it, ordering among itself by the sweep's draw order; the camera's own distance took over only when the view was turned or raised. Every triangle of a lofted strip carried one tile's slot, so a deck over a road, a ramp lane descending across tiles, a column or an arc cutting a corner could sit in front of what it was physically behind. Now there is one depth at every camera: how far a point lies along the way the camera looks, the turned column plus row into the screen at the cosine of the pitch and the height toward it at the sine, a level being 0.866 of a tile's diagonal step, in the 32-bit float buffer that was already there; at 30 degrees it is the isometric view's own distance, straight down it is the height alone. The art carries the same measure and writes it. A sprite is a quad standing on the corner of its footprint nearest the camera, a twentieth of a tile nearer than the corner so it wins over its own ground and stays behind the tile in front; standing art, a building, a tree, a car, a bridge, is a face rising from that corner, each row of it a point as many levels up as the rows above its bottom, so a tall building behind a low one shows over it exactly where it would and a hill hides what it really hides; flat art, the ground, the water, the underground lattice, a silhouette, lies down, its rows above the bottom receding along the ground. The instance carries which it is, with the tile's altitude and its painter's slot, in one number; the sweep's draw order and the turned camera's sort survive only as the tie between equals; the material bias a road strip and a deck take over what they lie on is unchanged from the free camera's. One thing keeps the painter: the original's art drawn alone, at the original's own camera. A slope tile's art is a height field, not a flat quad, and a first cut that stood every tile up, then laid it flat, let buildings bleed through rising slopes and cut trees to slivers; the original's algorithm is the definition of that frame, so with no mesh and no turn the camera uniform says so and the art composes by the sweep's slot exactly as before, tested but not writing depth, and the frame is the previous binary's pixel for pixel, measured at four views. With the mesh, or off that camera, everything is the camera's depth. Three more things the first 3D frames taught. A standing sprite is two quads meeting under the art's middle, since a building has two faces meeting at the corner nearest the camera and each recedes a tile for every tile it runs from that corner, half a tile's width of art being a tile of face; as one plane at the corner's distance a theatre's sign on its far corner had covered the office in front of it. The bias a road strip, a lane or a marking takes over what it lies on stays the free camera's third of a tile, cars over roads over ground: a fiftieth was tried, on the thought that everything is placed by where it is now, and the grass took a stretch of asphalt where the strip lies a hair under it between a tile's corners. And a water body's seabed, which mesh.c emits a quarter slot behind the surface so the surface wins inside the diamond, takes a twentieth of a tile of depth behind it, since a canal's bed lies at its own table and the surface had vanished. The mesh is untouched by any of it.

**The flash at the settle**. A quarter turn is eased over half a second and settles when the camera comes to rest: the pivot moves to the map's centre, the sweep is redone for the quarter and the anchor is held under the window's middle. The camera's quarter test reads any angle within a hundredth of a degree of a quarter as that quarter, and the ease's last step can land there while its own clock is a hair short of the end, since the ease's tail moves a third of a degree a frame. That frame is then drawn in the quarter's regime, the art unturned as at a snap, with the sweep of the quarter it left: the city turned twice, for one frame, until the next frame settles. Now the last hundredth of the ease arrives at once, so the frame that reaches the quarter is the frame that settles. The settle also redoes the sweep before it holds the anchor, since the hold measures against the sweep's origin. The proof is a new headless mode, ``--turn N`` with ``--shot``, which performs a quarter turn through the live loop's own per-frame advance at 60 Hz, writes every frame numbered and prints the camera's state per frame; the differences between neighbouring frames now fall monotonically to zero where they had jumped twice at the end. The live loop's per-frame advance, the clock, the sweep, the mesh, the traffic and the camera's move and settle, is one function, ``app_advance``, that both use.

**The settle draws nothing new**. With the double-turn frame gone, what remained at the settle was a cut: through the swing the art was the quarter's the camera had left, moved with its tiles, and at the settle the new quarter's sweep replaced it, mirrored art, other faces, and the silhouettes, which had been dropped for the swing, popped back. Now the sweep is made for the quarter the camera left until halfway through the swing and for the quarter it goes to from there, where the swing is fastest and a cut is least seen, and the settle draws the art the second half already drew. For that the art needed a turn of its own: a sweep made for a quarter is the city turned about the map's centre, so its art is drawn with the turn left from that quarter to the camera's angle, about the centre, plus the translation that puts a turn about the centre where the mesh's turn about the pivot is, which the vertex shader adds to the tile's turned position; at a settled quarter both are nothing and the art sits where the sweep put it. The silhouettes move with their tiles like the art and are drawn throughout. The same change fixed the half turn, where the sprites' camera had kept a cosine of minus one because only its sine was tested; with the art carrying real depth at every camera, half of it had failed the test there. The turn replay shows the art switch at the frame past the midpoint and the settle as the last small step, and sprite mode at the snap is still the previous binary's pixel for pixel.

A rail segment's corridor had been its own tiles, like a road's, so a corner could only be swept inside its tile, radius 0.4, a staircase was a chain of hooks, and two hooks meeting at 71,125 crossed their tracks. A road keeps to its tiles; a railway has two, and its runs may be free lines, as a highway's may. **A rail junction is a wye**. **Nothing raises a road or a railway**. Two pieces of machinery older than the notch did exactly that, and both are gone. A cross-section used to sit at the HIGHEST of five points across the band's width, so that the terrain could never cut through the road; where that lifted the band above the ground, a skirt of embankment blocks was drawn down to it at each edge, and a railway crossing a slope stood on a bank of its own with the ground falling away beside it. The corridor still does its work unchanged -- the tiles under a line are graded to it, raised or lowered, and walled at their sides -- so what carries a line across a dip is the ground, which is the one thing that is levelled. What is left is small: a band takes one height per station across its width, so where the corridor's shelf still twists under it the high side pokes through, by two to four centimetres on one or two tiles of a city and by a tenth of a level at the worst (Atlanta 51,48; Flarange 110,88; River5's two tiles), in eleven of the hundred and thirty-five cities swept. **Every triangle of a road or a railway lies on the terrain**. A band used to carry one height per station across its width, so where the ground twisted under it one side floated and the other dipped, and the same was true of a junction's asphalt, drawn as a fan across its tile. A ground-lying quad is now handed no height at all: the emitter clips it to the tiles it crosses as it always did, cuts each piece again on that tile's own fold -- the diagonal its top is drawn on -- and gives every vertex the drawn surface of the tile the piece landed in, which is the tile's height and not the neighbour's across a shared edge. The clip check, which samples every road triangle against the terrain over its footprint, now reports nothing on any of the hundred and thirty-five shipped cities, Maltron's long-standing hundred and thirty-five samples at 75,30 included: they were a junction's fan spanning the fold of its tile.

**A corridor's tiles are continuous, in the graph's terms**. A corridor's shelf is kept per tile and per corner, which is what lets two corridors lie side by side as two shelves with a wall between them; but each copy was written by whichever of the band's stations was nearest, so the tiles of ONE corridor could take the corner they share from different stations and disagree by half a level -- a step in the middle of a line. Two rules now hold, and they are the graph's. Along an edge: every copy that edge wrote of a corner takes the value of the nearest station it wrote any of them with, each lofted strip carrying its own identity while it is graded. At a node: the copies of a node tile's corners, whichever edge wrote them, are averaged and handed back to all of them, so every edge that meets there arrives at one level; the junctions mark their tiles as they are built (``shelf_node``). Two edges that merely run side by side share no node and are left alone. The check reported with the rest counts exactly what the rules forbid -- a shared corner disagreeing along one edge, or at a node -- judging each corner on its own, since a pair of tiles may share one corner along an edge and another between two edges: it is zero on all hundred and thirty-five shipped cities, where the first attempt (reconciling by family, and counting the worst of a tile pair's two corners) left 33 in Atlanta alone. A grade ceiling on the profile was tried alongside -- the family's ``shelf_grade``, which reaches the land beside a corridor but never the corridor's own tiles -- and taken out again: clamping each segment's pins bends it away from the node altitudes its neighbours also pin to, and the disagreements rose. The ceiling has to be settled across the graph, one level per node agreed by all its edges, before it can be applied to a line.

**Stage three runs once**. Each junction takes its shape from its arms and hands each of them back the length to start at; that is a computation and nothing else, no geometry comes out of it, and it was being done in full by both passes. It is now ``net_stage_three``, called by the grading pass alone, and the building pass reads the table it left. It may: the arms it reads are measured from the fitted path BEFORE any trim -- ``walk_segment`` runs ``seg_measure_arms`` ahead of ``seg_trim`` -- and the building pass replays the very segments the grading pass fitted, so both passes were working the same numbers from the same inputs. Doing it twice was also how the two passes came to disagree about a rail arm's cut and leave a raw slope under a junction's strip at Atlanta 51,50. The trap in making the change: ``build_networks`` clears the trim table at the top of every pass, so skipping the computation without also skipping the clear left it zeroed -- sixteen thousand triangles gone and the tight connectors nearly doubled, which is what the mesh hash is for. The level crossings that follow in the same stretch of code are a drawing and stay with the pass that draws. Proven output-identical: the sorted tile dump's hash unchanged, every check line unchanged, and all hundred and thirty-five shipped cities identical to the binary from before the change.

**The inspector points at the mesh**. View > Inspect, or command-I. Every land triangle carries the index of the component that made it: a run of triangles from one call site, broken when the geometry jumps, so one strip, one ramp, one lamp is one component. ``put_tri_r2`` is a macro that hands the emitter its caller's ``__func__`` and ``__FILE__``:``__LINE__``, and the road and rail funnels pass what they were given further down, so the name is the function that asked for the geometry rather than the clipper that cut it. A generating entry point -- ``loft``, ``build_junction`` -- announces its caller while it runs and leaves a note of the thing it makes: a strip's kind and ends, the pieces it was fitted as, its stations and their heights, its width, its pins and crosswalks; a junction's tile and links. The ids ride through the chunk sort with their triangles, in an array beside the vertex list, permuted by the same key. Pointing is then what it should be: the triangles in the tiles along the pointer's line of sight are projected the way the camera projects them, the one under the pointer wins, and the outline is that thing's silhouette, the edges no second triangle of it shares, drawn edge by edge. A triangle with no area on screen is turned away before the edge tests. A face seen edge on projects to a line, the pointer lies on one side of all three of its edges wherever it is, and the tests then answer yes to the whole window. The oblique camera makes such a face of every wall and skirt that runs along the view, so one of them, standing higher than the thing under the pointer, wins the pick and the outline lands where the pointer never was. The ground is not a thing to inspect. The query tool says what a tile is, so the pointer passes over the ground, its banks, its walls and its water. It also passes over the tints that lie ON the ground, such as the map view's zone colour, which covers every tile of the map as one component. What is built on the ground is what the pointer finds. The window is a table: the thing, the function that drew it and where it is written, what asked for it and where, the material, the triangle count, the extent, and the note line by line. ``--pick X,Y --inspect`` prints the same under a headless frame, with the count of outline edges; that frame is the live loop's own frame function, read back instead of presented, so a shot shows what the game draws. An edit carries the ids with it: the build before an edit is remembered, the splice takes each chunk's ids from the new list or the old one exactly as it takes its triangles, and the component table keeps the entries of the chunks that stand, so a pick after an edit names what is there. The traffic's prisms go through the same emitter every frame and record nothing: the table is written only while a build runs. ``--area`` prints, under its report, every function that emitted a land triangle on each tile with the material and the count, which is how the record is tested without a pointer.
